# CA-style test data for TwoB (synthetic, with answer keys)

Generated by `taxmind/synth_ca.py`. It mimics the **patterns** of one real month a CA firm shared (a Tally journal-register
export and the firm's flattened GSTR-2B working). **All data is invented**: supplier names, GSTINs (valid check digits),
PANs, addresses and invoice numbers. Nothing is copied from the real file. Return month: **June 2026**. April and May 2B
hold invoices booked late (reclaims) and July 2B holds late filers.

```bash
python -m taxmind.synth_ca --out test_data            # regenerate (deterministic, seed 11)
python -m taxmind.synth_ca --out /tmp/td --stress     # + stress_manufacturer (~4,800 books rows, ~5,300 2B rows/month, ~30 MB; not kept here)
python -c "from taxmind.bench_ca import run; run('test_data')"   # score the engine -> test_data/bench_report.json
python -m pytest -q tests/test_synth_ca.py            # generator sanity tests
```

## truth.json

```
meta      profile, client_gstin, return_period, months, files{...}, books_rows, portal_rows{period: n}, case_counts
rows[]    rid ('B:<excel row>' or 'P:<period>:<excel row>'), side, gid, file, sheet, row, source + row_ref (exactly
          the engine's Doc.source 'file.xlsx:Sheet' and Doc.row_ref 'row N'); books: true gstin, inv_no, inv_date,
          doc_type, signed tax; portal: key [gstin, invoice no, INV/CN/DN, period] (to map JSON docs), itc_available,
          rcm, amends, signed tax
groups[]  gid, case, category, supplier, books[rid], portal[rid] (the partner rows, in any month), partner_periods,
          traits[], itc_claim{igst,cgst,sgst,total} = ITC the CA claims in the June 3B before 17(5) reversal (signed),
          bucket (4A5_2b | 4A5_reclaim | 4A3_rcm | 4A5_2b_cn_books | none), blocked (Sec 17(5) rule id as in
          taxmind.blocked), blocked_exception (allowed look-alike for this client), lookalike_of, excluded (why no ITC),
          master_elig, note
table4    4A3_rcm, 4A5_auto_2b, 4A5_reclaim, 4A5_total, 4B1_current, 4B1_reclaimed, 4B1_total, 4B2_not_in_books,
          4D1_reclaimed, 4D2_not_available, net_itc (by head), and _method
```

**Table 4 method (the CA's Summary sheet):**
- **4A5** = the June 2B ITC (available, forward charge, net of credit notes and B2BA differences) + reclaims (invoices in the Apr/May 2B that were not booked then, reversed in 4B2 that month, and booked now).
- **4B1** = Sec 17(5) items claimed this month, current and reclaimed ("Reversal ITC - Construction/Ineligible 17(5) of Jun-26 / of Previous month").
- **4B2** = June 2B ITC not taken: not in books, booked without GST, held for wrong head or other GSTIN, and any excess over books. It also includes credit notes booked but not yet in 2B.
- **4D1** = reclaims.
- **4D2** = 2B ITC marked not available (Sec 16(4) / PoS).
- `net_itc = 4A5 + 4A3 - 4B1 - 4B2 = sum(groups.itc_claim) - 17(5) part`.

**Judgement calls in the key** (all documented in `groups[].note`; change them if your firm's policy differs):
- Amount differences are claimed at the lower of books / 2B.
- A ₹1-6 difference is accepted.
- Wrong head and other-GSTIN invoices are held (claim 0).
- An unbooked supplier credit note still reduces 4A5 (it is auto-populated).
- Airline / hotel / car-hire bills booked in another register are genuine (Pending/Accept, not Reject), but they are reversed in 4B2 because they are not in this purchase register.
- Car lease is blocked (17(5)(ab)) even though the vendor master says Yes.
- Buses with more than 13 seats, forklifts, goods-vehicle insurance, machine foundations / crane supports, a factory canteen under the Factories Act, food bought by a hotel, cement / steel / sub-contracts bought by a works contractor, and cars bought by a dealer are all allowed.

## Scoring (`taxmind/bench_ca.py`)

Each dataset is run three ways:
- `xlsx`: books xlsx + four 2B xlsx files.
- `csv`: books csv instead of xlsx.
- `json`: the June 2B as JSON instead of xlsx.

The 2B month is passed as a hint because the firm's file names don't carry MMYYYY. `period_detection` reports whether the engine could tell the month on its own. Reported for each run:
- link precision / recall (books row to 2B row);
- the per-case table (pair_ok / status_ok / action_ok / itc_ok);
- rows dropped by the loader or in no finding;
- engine ITC vs truth, overall and per case, plus engine `res.table4` vs truth table4;
- Sec 17(5) recall and false-flag rate, split into allowed exceptions and ordinary rows;
- invoice dates recovered from the narration;
- 2B Debit / Credit / B2BA / ITC-not-available rows read correctly;
- runtime.

It reads Findings defensively, so new Status values, attributes or engine fields don't break it.
`test_data/bench_report.json` holds the full result, with failure examples per case.
